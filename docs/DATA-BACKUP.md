# Data backup and restore

## What lives where

| Item | Location | In git? |
|------|----------|---------|
| SQLite database | `prisma/dev.db` | No (ignored) |
| Uploaded files | `public/uploads/` | No (ignored, `.gitkeep` only) |
| Secrets | `.env` | No (ignored) |
| Prisma client | `src/generated/prisma/` | No (regenerated by `npm install` / `npm run db:generate`) |
| Demo seed data | `prisma/seed.ts` | Yes |

A fresh clone gets a working app but **not** your real data — it only has whatever you create with `npm run db:seed` (demo content + `admin/admin123`).

## Local backup

Stop the dev/prod server first so the SQLite file is not being written:

```powershell
# 1. Copy the database (include -wal / -shm if present)
Copy-Item prisma\dev.db   backup\ -Force
Get-ChildItem prisma\dev.db-* -ErrorAction SilentlyContinue | Copy-Item -Destination backup\

# 2. Copy uploads
Copy-Item public\uploads   backup\uploads -Recurse -Force
```

Recommended backup folder layout:

```
backup\
  dev.db
  uploads\
  .env          # keep separately — contains JWT_SECRET
```

> Do not commit the backup folder. Use external storage (USB, cloud) or a private repo.

## Local restore

```powershell
# 1. Restore files (server must be stopped)
Copy-Item backup\dev.db prisma\dev.db -Force
Copy-Item backup\uploads\* public\uploads\ -Recurse -Force

# 2. Only if the schema changed since the backup:
npm run db:push

# 3. Start and verify
npm run dev
# → log in at http://localhost:3000/admin with an existing admin account
```

If restoring into a brand-new clone, also copy `.env` (or create it from `.env.example`) **before** starting.

## Docker backup / restore

In Docker the data already lives on the host via bind mounts, so no `docker cp` is needed:

```powershell
# Stop the app so the DB file is stable (db-push is a one-shot service)
docker compose stop app

# Backup
Copy-Item prisma\dev.db   backup\ -Force
Copy-Item public\uploads   backup\uploads -Recurse -Force

# Restore
Copy-Item backup\dev.db prisma\dev.db -Force
Copy-Item backup\uploads\* public\uploads\ -Recurse -Force

# Start again
docker compose up -d
```

Schema changes are applied automatically on the next `docker compose up` by the `db-push` service.

## Notes

- `npm run db:seed` is intended for an **empty** database. `SiteConfig` and `Admin` use `upsert`, but news/directions/staff/gallery/documents use `createMany` — running it twice duplicates content.
- On Windows, avoid copying `dev.db` while the app is running; SQLite file locks can produce a corrupted or stale copy.
- If `prisma/dev.db-wal` or `prisma/dev.db-shm` exist, copy them together with `dev.db` (they belong to the same database state).
- Uploaded files referenced by the DB must be restored to `public/uploads` with the same filenames, otherwise those images/documents will 404.
